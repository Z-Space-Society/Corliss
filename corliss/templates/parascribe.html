Parascribe

We run parascribe internally so our SCN users can manage their own audio transcriptions. Send an audio or video file and the system will return a transcript complete with segment and word timestamps.

Quickstart

1 · Set your key

Any key from API works. Export it as SCN_API_KEY as is done in the examples.

2 · Transcribe a file

curl {{ API_URL }}/v1/audio/transcriptions \
  -H "Authorization: Bearer $SCN_API_KEY" \
  -F file=@meeting.mp3 \
  -F model={{ example_model }}
import os
from openai import OpenAI  # pip install openai

client = OpenAI(
    base_url="{{ API_URL }}/v1",
    api_key=os.environ["SCN_API_KEY"],
)

with open("meeting.mp3", "rb") as audio:
    transcript = client.audio.transcriptions.create(
        model="{{ example_model }}",
        file=audio,
    )
print(transcript.text)

Transcription runs on the GPU at roughly 60 times real time, so an hour of audio comes back in about a minute.

Output

Pass response_format to choose an appropriate data type for your use-case.

FormatReturns
jsonTranscription text only (default).
textTranscription text as a plain string.
verbose_jsonTranscription text with timestamped segments and words (when requested).
srt, vttSubtitle files.

Word timings need timestamp_granularities[]=word alongside verbose_json: 

curl {{ API_URL }}/v1/audio/transcriptions \
  -H "Authorization: Bearer $SCN_API_KEY" \
  -F file=@meeting.mp3 \
  -F model={{ example_model }} \
  -F response_format=verbose_json \
  -F 'timestamp_granularities[]=word'
with open("meeting.mp3", "rb") as audio:
    transcript = client.audio.transcriptions.create(
        model="{{ example_model }}",
        file=audio,
        response_format="verbose_json",
        timestamp_granularities=["word"],
    )
for word in transcript.words:
    print(f"{word.start:8.2f}  {word.word}")

A short recording comes back like this:

{
  "task": "transcribe",
  "language": null,
  "duration": 2.4,
  "text": "Morning, everyone. Let's start.",
  "segments": [
    {"id": 0, "start": 0.08, "end": 1.12, "text": "Morning, everyone.", "speaker": null, "avg_logprob": -0.21},
    {"id": 1, "start": 1.44, "end": 2.32, "text": "Let's start.", "speaker": null, "avg_logprob": -0.17}
  ],
  "words": [
    {"word": "Morning,", "start": 0.08, "end": 0.56},
    {"word": "everyone.", "start": 0.64, "end": 1.12},
    {"word": "Let's", "start": 1.44, "end": 1.76},
    {"word": "start.", "start": 1.84, "end": 2.32}
  ],
  "usage": {...}
}

words is only returned when timings were asked for, and speaker is null when diarization is not enabled. language is used as a hint to detect the audio language.

The language is detected from the audio, so language and prompt are accepted and ignored.

Usage examples

Large files

If your files are large-ish (~10MB or bigger) they may be refused. For large files drop them somewhere publicly accessible and send their URL as the file: the upload's content is the link, and parascribe will fetch the audio itself.

printf 'https://media.example.com/meeting.mp3' | \
  curl {{ API_URL }}/v1/audio/transcriptions \
  -H "Authorization: Bearer $SCN_API_KEY" \
  -F 'file=@-;filename=source.url' \
  -F model={{ example_model }}
transcript = client.audio.transcriptions.create(
    model="{{ example_model }}",
    file=("source.url", b"https://media.example.com/meeting.mp3"),
)
print(transcript.text)

The link has to be direct without redirects. A share page that bounces to a download will fail and addresses on a private network are refused.

Speakers

Pass diarization=true for speaker / diarization support. Each segment in verbose_json will have a speaker such as SPEAKER_00, as well as words when using word timings. 

curl {{ API_URL }}/v1/audio/transcriptions \
  -H "Authorization: Bearer $SCN_API_KEY" \
  -F file=@meeting.mp3 \
  -F model={{ example_model }} \
  -F response_format=verbose_json \
  -F diarization=true
with open("meeting.mp3", "rb") as audio:
    transcript = client.audio.transcriptions.create(
        model="{{ example_model }}",
        file=audio,
        response_format="verbose_json",
        # Not part of the OpenAI API, so it rides in extra_body.
        extra_body={"diarization": "true"},
    )
for segment in transcript.segments:
    print(f"{segment.speaker}: {segment.text}")

The speaker count is determined automatically, but num_speakers, min_speakers, and max_speakers can all be used to set the value or used as hints to the diarizer.

Slow for now. Diarization runs on the CPU and takes about as long as the recording itself, so an hour of audio will take just under an hour to get the results. stream=true is ignored when using diarization.

Some OSS apps that (might) work with parascribe

The below meeting recorders / note taking apps all accept a custom OpenAI-compatible endpoint for transcriptions (BYOK). To setup pass it your API key, model (i.e. parakeet-v2, parakeet-v3), and the address in the last column.

Not supported by SCN. These are third-party apps we've found that can talk to the cluster. They're suggestions to get you started, and the SCN team doesn't maintain or support them.

AppPlatform(s)FunctionEndpoint
screenpipe macOS, Windows, Linux Records meetings and labels speakers itself Transcription, OpenAI Compatible: Endpoint {{ API_URL }}
anarlog macOS Meeting notes, transcribed after the call OpenAI provider, Advanced: Base URL {{ API_URL }}/v1
Buzz macOS, Windows, Linux Transcribes recordings you already have Preferences: Base URL {{ API_URL }}/v1/
Whisper for Obsidian Obsidian, including iOS and Android Records or imports audio into a note API URL {{ API_URL }}/v1/audio/transcriptions
Speakr Self-hosted web app Recording library with transcripts and summaries TRANSCRIPTION_BASE_URL={{ API_URL }}/v1/
Nextcloud OpenAI integration Self-hosted Nextcloud Transcribes Talk call recordings Service URL {{ API_URL }}/v1
Vexa Self-hosted Meeting bot for Meet, Teams and Zoom, with speaker labels TRANSCRIPTION_SERVICE_URL={{ API_URL }}

screenpipe and Vexa handle speakers on their own. For the rest they'll need to support an authenticated /asr endpoint.
